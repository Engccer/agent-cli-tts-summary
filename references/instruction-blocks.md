# 지침 블록

Claude, Codex, Gemini, Antigravity의 음성 요약이 일관되게 들리도록 같은 요약 형식 규칙을 사용한다.

경로가 반영된 지침 블록은 다음처럼 생성한다.

```bash
# --home 생략 시 현재 사용자 홈에서 자동으로 경로를 잡는다.
python scripts/render_instruction_block.py --agent codex --platform windows
# 다른 홈을 지정하려면 --home 으로 덮어쓴다.
python scripts/render_instruction_block.py --agent codex --platform windows --home <USER_HOME>/.codex
# 요약 언어를 바꾸려면 --language 를 준다(기본 한국어).
python scripts/render_instruction_block.py --agent claude --platform macos --language English
```

## 요약 언어 선택

- `--language` 기본값은 한국어이며, 한국어를 뜻하는 값(`ko`/`korean`/`한국어` 등)이면 한국어 블록을 출력한다.
- 그 외 값(예: `English`, `日本語`)이면 규칙 본문은 영어 블록으로 출력하고 첫 규칙 문장에 요약 언어를 지정한다. 임의 언어로 블록 전체를 번역할 수는 없으므로, 규칙은 에이전트가 확실히 이해하는 영어로 두고 요약 언어만 지시하는 방식이다.
- 언어를 바꾸면 설정 파일(`TTS-Summary/tts-config.txt`)의 음성 항목(`voice_sapi`/`voice_say`, `language_code`, `voice_elevenlabs`)도 그 언어에 맞게 함께 바꾼다. 훅 스크립트 자체는 언어를 강제하지 않는다.
- 지침 블록은 분량 규칙을 설정 파일의 `verbosity`(1~3단계)에 위임한다. 설정 통지 훅(UserPromptSubmit)이 매 턴 현재 단계와 문장 수를 알려 주며, 통지가 없는 CLI에서는 켬·3~6문장으로 간주한다.

## 설계 원칙: 지침은 최소, 판단은 훅으로

글로벌 지침은 세션마다 컨텍스트에 실리므로 에이전트가 스스로 판단해야 하는 것만 담는다. 결정론으로 만들 수 있는 것은 훅과 스크립트가 맡는다.

| 계약 | 담당 |
| --- | --- |
| 요약을 쓸지, 몇 문장으로 쓸지 | 설정 통지 훅이 매 턴 `[tts-config]` 한 줄로 알린다 |
| 요약 누락 | Stop hook의 누락 가드가 `exit 2`로 되돌린다 |
| 재생, 보관, 정리, 프로바이더 폴백 | Stop hook과 provider 스크립트 |
| 선택지 안내·중간 보고를 읽을지 | 스크립트가 설정의 `interim`을 확인한다 |
| 요약 파일 경로, 작성 순서, 일회용 파일, 문체, 중간 보고 명령 | 지침 블록(에이전트만 지킬 수 있는 것) |

## 표준 요약 규칙

- **작성 순서: 요약 파일을 먼저 쓰고, 본문 답변을 턴의 마지막 출력으로 낸다.** 마지막 텍스트 메시지만 제대로 보여주는 에이전트 CLI에서는 본문 뒤에 도구 호출이 오면 본문이 도구 호출 사이 텍스트로 밀려 화면·스크린 리더에서 유실된다. Stop hook은 턴 종료 후 파일만 읽으므로 요약을 먼저 써도 무방하다.
- TTS 요약은 지침 블록에 지정된 언어(기본 한국어)로 작성한다.
- 자기 인용이나 간접화법 같은 메타 서술을 피한다. “사용자가 물었다”, “설명했다” 같은 표현을 쓰지 않는다.
- 사용자가 바로 듣는 최종 브리핑처럼 직접 서술한다.
- 분량은 설정 통지의 상세 정도를 따른다. 1단계 1~2문장(결과만), 2단계 3~6문장(과정과 결정), 3단계 7문장 이상(근거·트레이드오프·후속 과제).
- 오류나 검증하지 못한 부분이 있으면 반드시 포함한다.
- 지침 파일에서 TTS 재생을 직접 호출하지 않는다. 음성 재생은 Stop hook이 담당하고, 긴 작업의 phase 전환 보고만 `play-tts-briefing` 스크립트로 한다.

## 임시 파일 수명주기

`tts-summary.txt`는 턴 하나짜리 일회용 파일이다. 지침 블록은 이 수명주기를 에이전트에게 명시해야 한다.

1. **생성**: 에이전트가 턴 종료 직전 새 파일로 한 번 쓴다.
2. **소비**: Stop hook이 파일을 읽어 음성을 생성·재생하고 `TTS-Summary/txt`에 보관본을 남긴다.
3. **삭제**: 훅이 임시 파일을 지운다(`assets/windows/stop-tts.ps1`의 `Remove-Item $SummaryFile -Force`, `assets/macos/stop-tts.sh`의 `rm -f "$SUMMARY_FILE"`). 이전 턴의 요약이 다음 턴에 다시 재생되는 것을 막는 의도된 동작이므로 훅에서 제거하지 않는다.

따라서 다음 턴이 시작될 때 파일은 존재하지 않는다. 에이전트는 매 턴 **새 파일 생성**으로 요약을 쓰고, 기존 파일의 삭제·교체를 먼저 시도하지 않는다. 이 계약이 빠지면 파일이 남아 있다고 가정한 편집 패턴이 매 턴 실패한다(`references/troubleshooting.md`).

## 경로 정확성

지침 블록의 임시 파일 경로, 설정 파일 경로, 중간 보고 스크립트 경로는 실제 훅 스크립트가 읽고 쓰는 경로와 같아야 한다. 보관 폴더는 훅만 알면 되므로 지침에 적지 않는다.
